Candidate Image Slimming Actions

  • The current image build now prunes pip._vendor.distlib/*.exe launcher files from new runtime images, and a rebuilt verification artifact confirmed they are absent after build.
  • The current image build now prunes site-packages/setuptools/cli.exe and site-packages/setuptools/gui.exe from new runtime images, and a rebuilt verification artifact confirmed they are absent after build.
  • Consider removing pip and possibly setuptools from the final runtime layer entirely if deployed environments do not install Python packages at runtime.
  • Keep python itself unless the entire runtime architecture changes; it is the interpreter your deployed Ubuntu environment actually executes.

When To Remove Them

  • Prefer removing these files during the image build or a deterministic pre-release slimming stage, before the final SIF hash, SBOMs, and provenance are generated.
  • Do not mutate the already-built release .sif as part of a post-build audit-only step. That changes the artifact bytes and fouls the recorded SHA256, SBOM, provenance, and any later signature/attestation story.

Platform Impact

  • Ubuntu / deployed Linux EC2: removing the Windows launcher .exe baggage should not affect normal runtime behavior, because those files are not part of the Linux execution path.
  • macOS: this project already treats Apptainer as a Linux-VM/Lima workflow, not a native macOS runtime. Removing Windows launcher .exe files should not change that model.
  • Windows: the .sif is not treated here as a native Windows executable. The documented path is WSL2 or another Linux environment. Removing Windows launcher .exe baggage from Python packaging inside the container should not improve or harm native Windows portability, because the runtime is still Linux-in-container.
  • Risk boundary: removing setuptools itself is higher risk than removing the .exe launcher stubs. If you prune setuptools, re-run smoke tests for WebUI startup, server startup, and at least one representative pipeline invocation.
